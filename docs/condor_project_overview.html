01What we built

A fleet of Hummingbot pmm_mister market-making bots on Binance BRL pairs, run by an AI agent on a closed, self-improving loop — no hand-tuning.

The agent reads the best-performing live controllers, generates parameter variants, backtests every variant at 1-second resolution on a local copy of the engine that is bit-identical to production, ranks them by profit and volume, gates the winners on out-of-sample validation and wallet budget, and — on a single human approval — reshapes the live fleet to the best set. Then it watches the live bots, compares real fills against the backtest, and turns that divergence into a trust score that sharpens the next round.

Why it's cheap & safe: the loop is deterministic code (a Condor CONTINUOUS routine), not an LLM-per-tick agent — zero tokens per lap, auto-restores after reboot, and nothing reaches live capital without a human pressing a button. A hard invariant guarantees it never touches any non-pmm_mister controller.

Optimizes parameters via a staged sweep (not brute force):
  • Base → backtest the live config as-is
  • One-at-a-time → vary each axis (TP, spread, inventory band, effectivization)
  • Mini-grid → combine the two highest-impact axes
Runs at 1-second fidelity because pmm_mister's sub-minute knobs (cooldowns, effectivization) are invisible at 1-minute. Long runs are chunked + stitched so they never freeze the engine.
Ranks on the right objective:
  • Business PnL = market PnL + (volume × rebate)
  • Volume (turnover → more rebate)
  • Risk-adjusted PnL (penalize drawdown + time underwater)
Proposes a whole new generation: pools every variant across all controllers, picks the global top-N (N = live count, so fleet size is stable), caps per-family for diversity, and autosizes capital to the budget. Propose nothing if nothing survives the gate.

The failures split cleanly in two — and this is the whole insight:
TypeFailuresFix
HOST Laptop sleeps/travels · Docker Desktop wedges (×2) · OOM SIGKILL · Tailscale flaps A proper always-on Linux server fixes these outright
CODE Startup-race → permanent death if a backend is down at boot · no liveness probe · stale-recycle · noop hides "broken" as "healthy" · no external staleness alarm The "do-first shortlist" — needed on any host
Key takeaway: a server move fixes the host-class failures but not the code-class ones. Moving without the shortlist just relocates the silent-stop bug to a nicer box. The code fixes are needed regardless of where it runs.
